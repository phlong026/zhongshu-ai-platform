## 目录命名说明

选择 `zhongshu-ai-platform`，原因是：

1. 与产品正式中文名“众墅之家 AI 赋能平台”一一对应；
2. 只使用小写英文和连字符，兼容 Git、Docker、CI/CD、Linux 路径与包管理工具；
3. 不绑定具体技术框架，未来从单体演进到多服务时无需改仓库名；
4. 避免使用 `ruoyi-*`，明确它是众墅之家的产品工程，而不是上游框架镜像。

## 本轮边界

本目录是唯一产品开发落点；来源仓库保持不变。完整源码作为资产库保留，运行时仅按白名单启用，不能因为 CRM、Mall、AI 等代码存在就把对应接口和任务全部打开。

| 目录 | 内容 | 边界 |
|---|---|---|
| `services/zhongshu-core` | 官方 JDK 17 完整后端，8,214 个文件 | System/Infra/Framework 是当前默认构建主线，其他模块按批次启用 |
| `apps/zhongshu-admin-web` | 完整 Vue3 管理端，2,780 个文件 | 唯一 Web 主工程 |
| `apps/zhongshu-miniapp` | 完整 Admin UniApp，2,711 个文件 | 小程序/H5/后续 Android、iOS App 主工程；不是已完成的多端产品 |
| `reference/donors/zhongshu-design` | 234 个设计专项差异文件及许可证 | 隔离参考，不接入主编译；设计 C 端身份不直接替代员工/组织模型 |

25 个导入文件仅清除了上游演示凭据或改为环境变量，SQL 表结构保持不变；原始与导入 blob 均已记录。不要在已跟踪的 `.env*` 模板写真实密钥，也不要用演示配置直接启动生产服务。完整范围和验证限制见迁入报告。

本轮没有实施真实 PostgreSQL、全平台身份、多组织权限、业务链、微信支付、AI Provider 或部署。D-07、D-09、D-10、D-11 状态不变。

## 文档同步规则

以下规则由主台账中的 `FND-DOC-001～003` 统一约束。任何架构、数据库、模块、身份权限、业务链、外部集成或验收状态发生变化时，必须在同一次变更中检查并同步：

1. 本 README 的阶段和决策摘要；
2. `docs/01-底座代码复用与改造方案.md` 的架构说明与决策快照；
3. `docs/02-一期底座需求规格与待决策台账.md` 的需求、验收和决策状态；
4. 后续对应的数据库、API、测试和部署文档。
5. 主台账中的实施证据登记；任何需求从 `DOCUMENTED` 提升状态时，必须同时登记代码/迁移、测试以及外部集成/UAT/部署证据或注明不适用原因。

只修改代码或只更新一份文档、导致不同文件保留不同技术选型和需求版本，不视为工作完成。阶段 0 必须提供可在本地运行的文档一致性检查，并在 CI 建立后作为合并门禁；在检查器真正实现并通过前，只能记录为 `DOCUMENTED`，不得声称同步门禁已经自动执行。
